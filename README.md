# ระบบรายงานการปฏิบัติต่อสัตว์ทดลองของนักวิจัย (PSU:LASC)

เว็บแอปไฟล์เดียว (single-file PWA) สำหรับให้นักวิจัยรายงานการปฏิบัติต่อสัตว์ทดลอง
โดยอ้างอิง **เลขที่โครงการวิจัย** ที่เจ้าหน้าที่ (แอดมิน) ดึงเข้าระบบจากระบบจริยธรรมการวิจัยในสัตว์
(animalethic.research.psu.ac.th)

## ไฟล์ในระบบ

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | ตัวระบบทั้งหมด (HTML + CSS + JavaScript) |
| `วิธีใช้งาน.html` | คู่มือการใช้งานสำหรับนักวิจัยและเจ้าหน้าที่ (เปิดอ่าน/สั่งพิมพ์ได้) |
| `วิธีติดตั้งแอป.html` | วิธีติดตั้งเป็นแอปบนคอมพิวเตอร์และมือถือ |
| `manifest.webmanifest` | ข้อมูลสำหรับติดตั้งเป็นแอป (PWA) — ไอคอน ทางลัด รูปตัวอย่าง |
| `sw.js` | Service worker — ใช้งานออฟไลน์ได้ และดึงเวอร์ชันใหม่อัตโนมัติ |
| `icon-192.png`, `icon-512.png`, `icon.ico` | ไอคอนแอป (`.ico` ใช้กับทางลัดบน Windows) |
| `screenshot-wide.png`, `screenshot-narrow.png` | รูปตัวอย่างที่แสดงในหน้าต่างติดตั้งแอป |
| `เปิดเป็นแอป.cmd` | เปิดระบบเป็นหน้าต่างแอปบน Windows (ไม่มีแถบเบราว์เซอร์) |
| `สร้างทางลัดบนเดสก์ท็อป.cmd` | สร้างไอคอนแอปไว้บนเดสก์ท็อป |
| `app-launcher.ps1` | สคริปต์เบื้องหลังของสองไฟล์ข้างบน |
| `app-url.txt` | ใส่ URL ของระบบที่เผยแพร่ เพื่อให้ตัวเปิดแอปเปิดเว็บแทนไฟล์ในเครื่อง |
| `firebase-config.js` | **ค่าการเชื่อมต่อ Firebase** ของระบบนี้ (แก้ไฟล์นี้ไฟล์เดียวเมื่อย้ายไปโปรเจกต์แยก) |
| `firebase-rules.json` | กฎความปลอดภัยสำหรับ**โปรเจกต์ Firebase แยกของระบบนี้** |
| `firebase-rules-shared-project.json` | กฎชุดเต็ม 3 ระบบ สำหรับช่วงที่ยังใช้โปรเจกต์ร่วม `psu-lasc-animal` |
| `apps-script-vet-alert.gs` | **ตัวกลางแจ้งเตือน (แนะนำ)** — Google Apps Script ส่ง LINE + อีเมล ฟรี ไม่ต้องมีเซิร์ฟเวอร์ |
| `apps-script-setup.md` | วิธีติดตั้ง Apps Script ทีละขั้น |
| `n8n-vet-alert-workflow.json` | workflow n8n แจ้งทีมสัตวแพทย์ทาง LINE + อีเมล (ทางเลือกแทน Apps Script) |
| `n8n-line-register-workflow.json` | workflow n8n รับคำขอ「ลงทะเบียน」ของสัตวแพทย์ผ่าน LINE OA |
| `n8n-vet-alert-setup.md` | วิธีตั้งค่า LINE OA · Firebase secret · n8n ทีละขั้น |
| `n8n-proxy-workflow.json` | workflow พร็อกซี n8n (ตัวเลือกเสริม สำหรับ「⚡ ดึงตรงจาก URL」) |
| `n8n-proxy-setup.md` | วิธีติดตั้งพร็อกซี พร้อมข้อควรระวังด้านความปลอดภัย |

## การติดตั้ง / ใช้งาน

รายละเอียดทั้งหมดอยู่ใน **`วิธีติดตั้งแอป.html`** — สรุปสั้น ๆ

| วิธี | ทำอย่างไร | เข้าสู่ระบบ/ซิงก์ |
|---|---|---|
| **ติดตั้งจากเว็บ (PWA)** — แนะนำ | อัปโหลดโฟลเดอร์ขึ้น `https://` แล้วกดปุ่ม「⬇ ติดตั้งแอป」ในระบบ หรือไอคอน ⊕ ท้ายแถบที่อยู่เว็บ | ได้ |
| **เปิดเป็นแอปจากไฟล์ (Windows)** | ดับเบิลคลิก `เปิดเป็นแอป.cmd` — เปิดเป็นหน้าต่างแอปไม่มีแถบเบราว์เซอร์<br>ดับเบิลคลิก `สร้างทางลัดบนเดสก์ท็อป.cmd` เพื่อสร้างไอคอนถาวร | ไม่ได้ (`file://`) |
| **เปิดไฟล์ตรง ๆ** | ดับเบิลคลิก `index.html` | ไม่ได้ |

* ติดตั้งแล้วจะมี **ทางลัดในไอคอนแอป** (คลิกขวาที่ไอคอน) ไปยัง รายงานใหม่ · ประวัติการรายงาน · สรุปผล
* มีเวอร์ชันใหม่เมื่อใด ระบบขึ้นแถบ「🔄 มีแอปเวอร์ชันใหม่」ให้กดอัปเดตได้ทันที (ตรวจทุก 30 นาที และเมื่อกลับมาที่แอป)
* เมื่อเผยแพร่ระบบขึ้นเว็บแล้ว ให้ใส่ URL ในไฟล์ `app-url.txt` และแก้ค่า `APP_URL` ใน `index.html`
  เพื่อให้ตัวเปิดแอปและข้อความแนะนำชี้ไปที่อยู่จริง
* **ไม่ใช่ไฟล์ติดตั้ง `.exe`** — เป็นเว็บแอปที่รันด้วยเบราว์เซอร์ที่มีอยู่แล้วในเครื่อง จึงไม่ต้องขอสิทธิ์ผู้ดูแลเครื่อง
  และอัปเดตทุกเครื่องพร้อมกันได้จากที่เดียว หากจำเป็นต้องได้ `.exe` จริง ต้องนำไปแพ็กด้วย Electron/Tauri เพิ่มเติม
* ข้อมูลบันทึกใน **localStorage ของเบราว์เซอร์เครื่องนั้น** — ควรกด「⬇ สำรองข้อมูล (JSON)」เป็นระยะ
  และใช้「⬆ นำเข้าข้อมูล」เพื่อรวมข้อมูลจากเครื่องอื่น

## ฐานข้อมูลกลาง (Firebase) — แยกเป็นของระบบนี้ตั้งแต่เวอร์ชัน 1.5.0

ค่าการเชื่อมต่อ Firebase อยู่ในไฟล์ **`firebase-config.js`** ไฟล์เดียว (ไม่ต้องแก้ `index.html`)

| ช่วง | โปรเจกต์ | `LASC_CLOUD_ROOT` | กฎที่ใช้ |
|---|---|---|---|
| **ที่ใช้อยู่ — โปรเจกต์แยกของระบบนี้** | `psu-lasc-animal-report` | `animalReport` | `firebase-rules.json` (เฉพาะระบบนี้) |
| ของเดิม (ถ้าต้องย้อนกลับ) | `psu-lasc-animal` ใช้ร่วมกับระบบยา/ระบบจองเครื่องมือ | `data/animalReport` | `firebase-rules-shared-project.json` (กฎชุดเต็ม 3 ระบบ) |

> บัญชีผู้ใช้ของ Firebase แยกตามโปรเจกต์ — **ผู้ใช้เดิมต้องลงทะเบียนใหม่ในระบบนี้แล้วให้เจ้าหน้าที่อนุมัติ**
> (บัญชีของระบบยาและระบบจองเครื่องมือยังอยู่ที่โปรเจกต์เดิมตามปกติ)

```
{ROOT}/projects/{id}          ทะเบียนโครงการ — เจ้าหน้าที่เขียน · ผู้ล็อกอินทุกคนอ่านได้
{ROOT}/users/{uid}            ข้อมูลลงทะเบียนนักวิจัย — เจ้าของเขียน · เจ้าหน้าที่อ่าน
{ROOT}/members/{uid}          ผลการอนุมัติบัญชี (approved / rejected / suspended) — เจ้าหน้าที่เขียน · เจ้าของอ่าน
{ROOT}/reports/{uid}/{id}     รายงาน — เขียนได้เมื่อบัญชีได้รับอนุมัติแล้ว · เจ้าหน้าที่เห็นทั้งหมด
{ROOT}/alerts/{uid}/{id}      แจ้งเหตุ/ปัญหาสุขภาพสัตว์ของสมาชิกที่อนุมัติแล้ว (ผู้แจ้งลบ/เปลี่ยนสถานะเองไม่ได้)
{ROOT}/guestAlerts/{id}       แจ้งเหตุจากผู้ที่ยังไม่อนุมัติ/ไม่ได้เข้าสู่ระบบ — เขียนครั้งเดียว · อ่านได้เฉพาะเจ้าหน้าที่
{ROOT}/vets/{id}              ผู้รับแจ้ง (สัตวแพทย์ / กลุ่ม LINE) — เจ้าหน้าที่เท่านั้น
{ROOT}/vetRequests/{lineId}   คำขอเชื่อม LINE ที่ตัวกลางแจ้งเตือนบันทึกไว้ รอเจ้าหน้าที่อนุมัติ
{ROOT}/notifyLog/…            บันทึกกันแจ้งซ้ำของตัวกลางแจ้งเตือน
{ROOT}/settings/public        เบอร์โทรฉุกเฉิน · อีเมลสำรอง · Webhook ของตัวกลางแจ้งเตือน — ทุกคนอ่านได้ · เจ้าหน้าที่เขียน
allowed/{uid} = true          รายชื่อเจ้าหน้าที่ (ได้สิทธิ์แอดมิน และไม่ต้องรออนุมัติ)
```

### วิธีแยก Firebase ไปโปรเจกต์ของระบบนี้ (ทำครั้งเดียว ~20 นาที)

> สถานะ: `firebase-config.js` ชี้ไปที่โปรเจกต์ `psu-lasc-animal-report` แล้ว (ข้อ 1 และ 4 เสร็จแล้ว)
> เหลือข้อ 2, 3, 5–9 ที่ต้องทำใน Firebase Console และ n8n

1. <https://console.firebase.google.com> → **Add project** (เช่น `psu-lasc-animal-report`)
2. **Build → Authentication → Get started → Email/Password: Enable**
   และ **Settings → Authorized domains** เพิ่มโดเมนที่เผยแพร่ระบบ (เช่น `kwanchanokd.github.io`)
3. **Build → Realtime Database → Create database** (เลือก `asia-southeast1` Singapore) → **Rules** → วาง `firebase-rules.json` → **Publish**
4. **Project settings → Your apps → Web (`</>`)** → คัดลอกค่า `firebaseConfig` ไปแทนใน `firebase-config.js`
   และเปลี่ยน `window.LASC_CLOUD_ROOT = 'animalReport';`
5. **ย้ายข้อมูลเดิม** — ที่โปรเจกต์เดิม เปิด Realtime Database → คลิกโหนด `data/animalReport` → ⋮ **Export JSON**
   → ที่โปรเจกต์ใหม่ สร้างโหนด `animalReport` → ⋮ **Import JSON** เลือกไฟล์นั้น
6. **บัญชีผู้ใช้ไม่ย้ายตามอัตโนมัติ** (Authentication แยกต่อโปรเจกต์) — ให้ทุกคนลงทะเบียนใหม่ในระบบ
   แล้วเจ้าหน้าที่กดอนุมัติ (รายงานเดิมยังอยู่ แต่ผูกกับ uid เดิม — เจ้าหน้าที่ยังเห็นครบทุกรายการ)
   ถ้าต้องการย้ายบัญชีพร้อมรหัสผ่านเดิม ใช้ Firebase CLI `firebase auth:export` / `auth:import` (ต้องใช้ค่า hash ของโปรเจกต์เดิม)
7. ลงทะเบียนบัญชีเจ้าหน้าที่ในระบบ → คัดลอก **User UID** จาก Authentication → เพิ่มที่ Realtime Database `allowed/{uid}` = `true`
8. อัปเดตตัวกลางแจ้งเตือนให้ชี้โปรเจกต์ใหม่ — Apps Script: แก้ `FB_DB_URL` / `FB_DB_SECRET` / `FB_ROOT` ในไฟล์สคริปต์ แล้ว Deploy เวอร์ชันใหม่ (n8n: แก้ `LASC_FB_*`)
9. อัปโหลด `firebase-config.js` ขึ้นเว็บ — เมื่อทุกอย่างทำงานแล้ว ลบส่วน `animalReport` ออกจากกฎของโปรเจกต์เดิมได้

> ระหว่างที่ยังใช้โปรเจกต์ร่วม ให้วาง **`firebase-rules-shared-project.json`** (กฎชุดเต็มของ 3 ระบบ) ในโปรเจกต์เดิม
> ⚠️ อย่าวาง `firebase-rules.json` ในโปรเจกต์ร่วม เพราะจะลบกฎของระบบยาและระบบจองเครื่องมือ

## ลงทะเบียนนักวิจัย และการอนุมัติโดยแอดมิน

**นักวิจัย** กด「🔑 เข้าสู่ระบบ」→ แท็บ「📝 ลงทะเบียนนักวิจัย」→ กรอก ชื่อ–สกุล · อีเมล · รหัสผ่าน (หน่วยงาน/เบอร์โทรไม่บังคับ) → ลงทะเบียน

| สถานะบัญชี | สิ่งที่เกิดขึ้น |
|---|---|
| ⏳ **รออนุมัติ** | ใช้งานได้ครบ รายงานเก็บในเครื่อง · เห็นทะเบียนโครงการ · **แจ้งเหตุฉุกเฉินได้ทันที** (เข้ากล่องผู้แจ้งทั่วไป) |
| ✅ **อนุมัติแล้ว** | รายงานที่บันทึกระหว่างรอ**ส่งขึ้นระบบกลางอัตโนมัติ** และซิงก์ทุกเครื่อง · ติดตามสถานะการแจ้งเหตุได้ |
| ⛔ **ไม่อนุมัติ / ⏸ ระงับ** | ใช้งานแบบเก็บในเครื่องเท่านั้น กฎฐานข้อมูลปฏิเสธการเขียนขึ้นระบบกลาง |

**แอดมิน** เข้าสู่ระบบด้วยบัญชีเจ้าหน้าที่ → แท็บ「👥 สมาชิก / สัตวแพทย์ (แอดมิน)」(ตัวเลขสีแดง = รออนุมัติ)
→ กด **✅ อนุมัติ** / **⛔ ไม่อนุมัติ** รายคน หรือติ๊กหลายคนแล้วกด **✅ อนุมัติที่เลือก** · ระงับบัญชีที่อนุมัติแล้วได้ (⏸)
— ถ้าต่อ n8n ไว้ นักวิจัยจะได้อีเมลแจ้งผล และผู้รับแจ้งที่เลือกไว้จะได้ LINE เมื่อมีผู้ลงทะเบียนใหม่

* บัญชีที่มีอยู่แล้วแต่ยังไม่เคยกรอกข้อมูลลงทะเบียน ระบบจะเปิดกล่องให้กรอกเมื่อเข้าสู่ระบบ
* เปิดจากไฟล์ในเครื่อง (`file://`) จะเข้าสู่ระบบไม่ได้ — ต้องเปิดผ่าน `https://` (แก้ `APP_URL` ใน `index.html`)

## สิทธิ์การใช้งาน

| บทบาท | สิ่งที่ทำได้ |
|---|---|
| นักวิจัย (ค่าเริ่มต้น) | เลือกเลขที่โครงการ → กรอกข้อมูลสัตว์ → เลือกรายการที่รายงาน → บันทึก / พิมพ์ PDF / ดูสรุป · แจ้งเหตุฉุกเฉิน |
| แอดมิน (เจ้าหน้าที่) | ทะเบียนโครงการ + ดึงข้อมูลจากระบบจริยธรรมฯ · อนุมัตินักวิจัย · จัดการทีมสัตวแพทย์ผู้รับแจ้ง · กล่องรับแจ้งเหตุ |

สิทธิ์แอดมินมี 2 ทาง

1. **ยืนยันจากคลาวด์ (ของจริง)** — เข้าสู่ระบบด้วยบัญชีที่ uid อยู่ใต้ `allowed` ระบบจะเปิดโหมดแอดมินให้เอง
   และกฎความปลอดภัยของ Firebase เป็นผู้บังคับใช้สิทธิ์จริง ข้ามไม่ได้
2. **รหัสผ่านในเครื่อง (สำรองตอนออฟไลน์)** — ค่าเริ่มต้น **`lasc2569`** เปลี่ยนได้โดยเรียก `changeAdminPin()`
   ใน Console ของเบราว์เซอร์ (เก็บใน localStorage ของเครื่องนั้น)
   ทางนี้เป็นเพียงการกันเข้าใช้โดยไม่ตั้งใจ **ไม่ใช่ระบบความปลอดภัยจริง** — เปิดหน้าจอแอดมินได้
   แต่ถ้าไม่ได้รับสิทธิ์บนคลาวด์ การเขียนทะเบียนโครงการขึ้นคลาวด์จะถูกฐานข้อมูลปฏิเสธ

## ขั้นตอนของแอดมิน — ดึงข้อมูลจาก animalethic.research.psu.ac.th

ระบบจริยธรรมฯ **ต้องล็อกอิน** (เรียก `/home` โดยไม่ล็อกอินจะถูกส่งไป `/logout`) และ**ไม่ได้เปิด CORS**
ให้เว็บโดเมนอื่นอ่านข้อมูล เบราว์เซอร์จึงบล็อกการ fetch ข้ามโดเมนจากหน้านี้เสมอ
ระบบจึงเตรียมช่องทางไว้ 3 แบบ ในแท็บ「🗂 ทะเบียนโครงการ」(โหมดแอดมิน)

### วิธีที่ 1 — Bookmarklet 🔖 (แนะนำ ใช้ได้จริงเสมอ)

สคริปต์ทำงาน**บนหน้าเว็บของระบบจริยธรรมฯ เอง** ขณะที่ท่านล็อกอินอยู่ จึงไม่ติด CORS และใช้สิทธิ์ของท่านเอง

1. ลากปุ่มเขียว **「🔖 ดึงข้อมูล animalethic」** ไปวางบนแถบบุ๊กมาร์ก
   (หรือกด「📋 คัดลอกโค้ด Bookmarklet」แล้วสร้างบุ๊กมาร์กใหม่ วางโค้ดในช่อง URL)
2. เปิด animalethic.research.psu.ac.th → ล็อกอิน → ไปหน้ารายการโครงการ (`/home`) หรือหน้า protocol
3. กดบุ๊กมาร์ก — สคริปต์จะเก็บข้อความหน้านั้น และถามว่าจะไล่ดึงรายละเอียดโครงการที่มีลิงก์ในหน้าหรือไม่
   (สูงสุด 60 โครงการ ดึงทีละหน้า เว้นระยะ 0.25 วินาที) แล้วบันทึกไฟล์ `animalethic-export.json`
   พร้อมคัดลอกลง clipboard
4. กลับมาที่ระบบนี้ → **「⬆ นำเข้าไฟล์จาก Bookmarklet」** → เลือกไฟล์ → ตรวจทานตาราง → **「💾 นำเข้ารายการที่เลือก」**

### วิธีที่ 2 — ดึงตรงจาก URL ⚡

กด「⚡ ดึงตรงจาก URL」จะได้ผลเฉพาะกรณีต่อไปนี้เท่านั้น
* นำระบบนี้ไปโฮสต์ใน**โดเมนเดียวกับ** animalethic (same-origin), หรือ
* ผู้ดูแลระบบจริยธรรมฯ เปิด CORS ให้โดเมนของระบบนี้, หรือ
* ใส่ **URL พร็อกซี** ในช่องที่เตรียมไว้ (เช่น n8n / Google Apps Script ที่ล็อกอินแทนได้)
  รองรับรูปแบบ `https://proxy/...?url={url}` หรือพร็อกซีที่ต่อท้ายด้วย URL ที่ encode แล้ว

หากถูกบล็อก ระบบจะแจ้งสาเหตุและทางแก้ให้ครบ ไม่ทำให้หน้าเว็บค้าง

### วิธีที่ 3 — วางข้อความ (paste)

เปิดหน้า protocol กด「More info」→ `Ctrl+A` → `Ctrl+C` → วางในกล่องข้อความ → กด「⚡ แยกข้อมูลอัตโนมัติ」
ถ้าข้อความมีหลายโครงการ ระบบจะเปิดหน้าตรวจทานให้เลือกนำเข้าทีละหลายรายการ

### ข้อมูลที่ดึงได้อัตโนมัติ

เลขที่โครงการ (Protocol Code) · ชื่อโครงการ (Title Thai/English) · หัวหน้าโครงการ (Principle investigator) ·
อีเมล/เบอร์โทร (Emergency contact) · ชนิดสัตว์ · สายพันธุ์ · เพศ (จากตาราง Number/Age) ·
จำนวนที่อนุมัติ (Total sample size) · วันหมดอายุ (แปลง พ.ศ. → ค.ศ. ให้)

การนำเข้าซ้ำจะ**อัปเดตเฉพาะช่องที่ยังว่าง** ไม่ทับข้อมูลที่เจ้าหน้าที่แก้ไว้
และ**ควรตรวจทานกับเอกสารอนุมัติจริงก่อนใช้งานเสมอ**

## ขั้นตอนของนักวิจัย — รายงาน

1. เลือก **เลขที่โครงการวิจัย** (ระบบแสดงข้อมูลโครงการและจำนวนสัตว์คงเหลือให้)
2. กรอก **ชนิดสัตว์ทดลอง / เพศ / สายพันธุ์ / จำนวน** (ระบบเติมค่าจากโครงการให้อัตโนมัติ แก้ไขได้)
3. เลือก **รายการที่ต้องการรายงาน** อย่างใดอย่างหนึ่ง
   * **การุณยฆาต (Euthanasia)** → ต้องเลือกวิธีการเพิ่มเติม
     * Overdose anesthetic drug injection (การฉีดยาสลบเกินขนาด)
     * Overdose anesthetic drug inhalation (การสูดดมยาสลบเกินขนาด)
     * Carbondioxide inhalation (การสูดดมก๊าซคาร์บอนไดออกไซด์)
   * **Off-site transport of laboratory animals** → ระบุสถานที่ปลายทาง (บังคับ) และรายละเอียดการขนย้าย
   * **Died during the study** → ระบุวันที่พบสัตว์ตาย (บังคับ) สาเหตุ การชันสูตร ฯลฯ
4. กรอกวันที่ดำเนินการและผู้รายงาน → กด「💾 บันทึกรายงาน」
   ระบบออกเลขที่รายงานอัตโนมัติในรูปแบบ `AR-<ปี พ.ศ.>-####`

## การควบคุมจำนวนตามที่ได้รับอนุมัติ

ระบบรวมจำนวนสัตว์จากทุกรายงานของโครงการเทียบกับจำนวนที่ได้รับอนุมัติ และแสดงแถบคงเหลือแบบเรียลไทม์
หากรวมแล้วเกิน ระบบจะเตือนและให้ยืนยัน เมื่อบันทึกจะติดป้าย **「เกินจำนวนอนุมัติ」**
ในประวัติการรายงานเพื่อให้เจ้าหน้าที่ตรวจสอบ (ไม่บล็อกการบันทึก)

## แจ้งเหตุฉุกเฉิน / ปัญหาสุขภาพสัตว์ทดลอง → ทีมสัตวแพทย์ ทาง LINE + อีเมล

ปุ่มแดง「🚨 แจ้งเหตุฉุกเฉิน」มุมขวาบน และแท็บ「🚨 แจ้งเหตุ / สุขภาพสัตว์」

**นักวิจัย** เลือกประเภท (🚨 เหตุฉุกเฉิน / 🩺 ปัญหาสุขภาพสัตว์) → ระดับความเร่งด่วน (วิกฤต / เร่งด่วน / ทั่วไป)
→ สัตว์ที่พบปัญหา (โครงการ สถานที่ ชนิด เพศ สายพันธุ์ จำนวน กรง) → อาการ (checklist) รายละเอียด การดำเนินการเบื้องต้น
→ ชื่อและเบอร์โทรที่ติดต่อได้ทันที → กดส่ง ระบบออกเลขที่ `VA-<พ.ศ.>-<ววดด>-XXXX` แล้ว

1. บันทึกเข้ากล่องรับแจ้งของทีมสัตวแพทย์บนระบบกลาง — สมาชิกที่อนุมัติแล้วเข้ากล่องของตนเอง (ติดตามสถานะได้)
   ผู้ที่ยังไม่อนุมัติ/ไม่ได้เข้าสู่ระบบเข้า**กล่องผู้แจ้งทั่วไป** (เหตุฉุกเฉินแจ้งได้เสมอ ไม่ต้องรออนุมัติ)
2. **ตัวกลางแจ้งเตือนส่ง LINE + อีเมลถึงสัตวแพทย์ทันที** ตามระดับความเร่งด่วนที่แต่ละคนเลือกรับ
   — ถ้าตัวกลางขัดข้อง ระบบให้กด「✉ เปิดร่างอีเมล」ถึงอีเมลสำรองแทน
3. แสดงปุ่มโทรเบอร์ฉุกเฉิน และเตือนให้โทรทันทีเมื่อเป็นกรณีวิกฤต

**แนบรูปภาพได้สูงสุด 3 รูป** (ถ่ายจากมือถือได้ทันที) — ระบบย่อรูปให้เหลือด้านยาวไม่เกิน 1280 px ขนาดราว 200 KB ต่อรูป
ก่อนส่ง · รูปแสดงในหน้ารายละเอียดเรื่องและในแบบพิมพ์ PDF · ข้อความแจ้งเตือนทาง LINE/อีเมลจะบอกจำนวนรูปและให้เปิดดูในระบบ
· รูปเก็บบนระบบกลางเท่านั้น (ไม่เก็บใน localStorage เพื่อไม่ให้พื้นที่เบราว์เซอร์เต็ม) ถ้าแจ้งขณะออฟไลน์ล้วน รูปจะไม่ถูกบันทึก

**ทีมสัตวแพทย์ (บัญชีเจ้าหน้าที่)** เห็นทุกเรื่อง เรียงเรื่องวิกฤตที่ยังไม่ปิดไว้บนสุด · หน้าจอที่เปิดแอปค้างไว้
**เด้งแจ้งเตือน + เสียง** เมื่อมีเรื่องใหม่ (กด「🔔 เปิดการแจ้งเตือนบนเครื่องนี้」ครั้งแรก) · กด「🩺 ดำเนินการ」เปลี่ยนสถานะ
`รอรับเรื่อง → รับเรื่องแล้ว → กำลังดูแลรักษา → ปิดเรื่องแล้ว` — ระบบแจ้งความคืบหน้าในทีมทาง LINE (ให้รู้ว่าใครรับเรื่องแล้ว)
และส่งอีเมลแจ้งผลถึงผู้แจ้ง · ถ้าปิดด้วยผล「การุณยฆาต」หรือ「สัตว์ตาย」 ผู้แจ้งกด「📝 ทำรายงานจากเรื่องนี้」เพื่อเติมฟอร์มรายงานให้อัตโนมัติ

### ตั้งค่าครั้งเดียว (เจ้าหน้าที่)

เลือกตัวกลางแจ้งเตือน 1 แบบ — **Google Apps Script** (ฟรี ไม่ต้องมีเซิร์ฟเวอร์ · คู่มือ `apps-script-setup.md`)
หรือ **n8n** (ถ้ามีเซิร์ฟเวอร์อยู่แล้ว · คู่มือ `n8n-vet-alert-setup.md`) — ทั้งสองแบบให้ผลเหมือนกันทุกประการ

1. วางกฎ Firebase ชุดใหม่ (`firebase-rules.json` ในโปรเจกต์แยก หรือ `firebase-rules-shared-project.json` ในโปรเจกต์ร่วม) → **Publish**
2. สร้าง LINE Official Account + เปิด **Messaging API** → ออก **Channel access token** · คัดลอก **Database secret** ของ Firebase
3. ติดตั้งตัวกลาง
   * **Apps Script** — วางโค้ด `apps-script-vet-alert.gs` ที่ script.google.com → กรอก CONFIG → Run `setupTest` →
     Deploy เป็น Web app (Execute as: Me · Who has access: Anyone) → ได้ URL `…/exec`
   * **n8n** — ตั้งค่าตัวแปร → นำเข้า `n8n-vet-alert-workflow.json` และ `n8n-line-register-workflow.json` → Active
4. ในระบบ แท็บ「👥 สมาชิก / สัตวแพทย์」→ ใส่ Webhook URL + รหัสเชื่อมต่อ + เบอร์โทรฉุกเฉิน → บันทึก → 🔔 ทดสอบ
5. ที่ LINE Developers Console → Webhook URL = URL เดียวกัน → เปิด Use webhook → Verify
6. **เพิ่มสัตวแพทย์** — ให้สัตวแพทย์พิมพ์ `ลงทะเบียน ชื่อ-สกุล` ใน LINE OA (หรือ `ลงทะเบียน` ในกลุ่ม LINE)
   → เจ้าหน้าที่กด「➕ เพิ่มเป็นผู้รับแจ้ง」→ บันทึก → 🔔 ทดสอบ — **เพิ่มคนใหม่เมื่อไรก็ได้ ใช้ได้ทันที ไม่ต้องแก้สคริปต์**
   (หรือกรอกเฉพาะชื่อ + อีเมลก็ได้ ไม่ต้องใช้ LINE)

ก่อนต่อตัวกลางแจ้งเตือน: อีเมลสำรอง = `psu.labanimals@gmail.com` · ยังไม่มีเบอร์โทรฉุกเฉิน · ไม่มีการแจ้งเตือนอัตโนมัติ
